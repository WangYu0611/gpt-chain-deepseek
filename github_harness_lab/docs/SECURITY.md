# 安全边界与上线门槛

本原型不承担 Windows 安全沙箱功能。所有默认入口仅离线运行，真实执行与发布桥保持 BLOCKED。将 JSON 布尔值改为 true 不能证明隔离、预算或授权已实现。

## 信任划分

可信控制区负责校验事件来源、可信作者、当前 Issue 状态和仓库策略，确定测试 argv、管理状态/证据、检查提交范围并准备 outbox。Agent 执行区只能接收批准的任务副本和源码，不应获取发布凭据。未来发布区需独立身份、重新读取远程 head/任务状态后才推任务分支和创建/更新同一 PR。

| 控制 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| `allowed_paths` 与 diff 检查 | 准备提交的变更路径符合策略 | Agent 未读取其他文件、未联网或没有驻留进程 |
| clean clone / worktree | 代码与工作副本分开 | 用户级凭据和系统资源已隔离 |
| 删除 GitHub 环境变量 | 子进程环境没有这些变量 | 相同用户无法读父进程、凭据文件、Git config 或 Runner token |
| 日志脱敏和哈希 | 特定已知秘密被移除、文件内容未改变 | 未知秘密从未泄露、产物来源一定可信 |
| 测试退出码与 Manifest | 外层观察到的检查结果和提交关联 | 测试覆盖足够、修改后的测试没有被削弱 |
| CLI workspace-write 权限 | 具体版本声明的 Harness 授权模式 | Windows 内核强制沙箱或网络隔离 |

因此测试 F 的“不能泄露密钥/访问禁止资源”必须在专用 VM / 受限用户和网络策略下实测。通过路径单元测试不等于通过完整权限隔离验收。

## 推荐部署隔离

专用 VM 或可销毁执行节点优先；使用独立非管理员账户，禁止读个人用户目录、OneDrive、浏览器配置、SSH、云凭据和其他项目；限定网络出站到批准的供应商/API，按任务决定是否允许依赖下载。执行区不挂载控制器状态、授权文件、可信测试脚本或发布区凭据。不要使用 SYSTEM 或交互管理员账户运行 Agent。

Runner 监听来自受信仓库的任务；GitHub 托管的任务书不自动可信。事件快照必须通过认证 GitHub API 再读回，而不是仅相信本地传入 JSON。校验 repository、Issue 作者、标签操作者、依赖、标签与当前状态。拒绝 fork / 外部 PR 的代码在长期持有凭据的 self-hosted Runner 上自动执行。GitHub 官方也建议自托管 Runner 用于私有仓库，见 [Adding self-hosted runners](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners)。

## 执行策略

- 默认保护 `.git`、`.github`、凭据、控制器、授权文件和配置。任务范围只能收窄可信配置，不能放宽它。拒绝绝对路径、`..`、符号链接/reparse point、大小写绕过与路径前缀混淆。
- Issue 仅给出配置中的 `test_ids`。外层命令使用 argv 数组、`shell=False`，固定工作目录、环境白名单与超时；不执行 Issue 内的任意命令文本。项目测试本身也是不可信代码，仍须隔离运行。
- 校验 DSH 进程退出码、NDJSON final 状态和 session，再独立执行测试、检查 diff、收集 Git SHA。模型输出不能更改状态机、成本额度或测试结果。
- 对每次运行设置进程树超时、日志大小/磁盘余量限制、失败次数和至多三次自动返工。供应商硬额度应独立设置；仅有 timeout 或 token 估算不足以保证费用上限。
- 控制器与 Agent 分离用户/VM 才能防止改写 Manifest、SQLite、outbox 和授权文件。outbox 摘要仅为完整性校验；若生成者能同时改内容和摘要，不能视为签名或授权证明。
- 默认不合并。保护分支与所需 CI 在 GitHub 服务端强制执行；Worker token 不得具备 bypass。验收记录必须关联当前 head，提交更新后旧验收不再有效。

## 秘密与日志

示例配置不得包含密钥。实际授权文件、运行状态、原始 Harness 流、错误日志、测试产物和真实配置不得入库。不要把 token 放进 git URL、shell 命令、PR 内容、Issue、截图或性能报告。

只有可信控制器筛选的测试日志和产物才能进入待发送清单；原始 Harness 流默认仅本地受限保存。上传前检查可能包含路径、用户名、环境变量、源码秘密和屏幕隐私。脱敏是补充措施，无法代替不给 Agent 访问秘密。

如发现泄露，立即关闭上线开关、停止专用 Runner 和网页任务，撤销暴露凭据；保留受限取证副本，清理远程历史/Artifacts 需按仓库管理员流程处理，不直接删状态来掩盖事件。
